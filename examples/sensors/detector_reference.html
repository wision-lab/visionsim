simulate_photon_timestamps

The Monte-Carlo reference for the active-SPC photon flux → detection stage. It turns a per-bin arrival rate into the raw detection timestamps a TDC would emit — with dead time, quench behaviour and hit caps all modelled explicitly, rather than assumed away by a closed form.

What it simulates signal path

One pixel, n_pulses laser cycles, n_tbins time bins per cycle. Everything downstream of the arrival rate is sampled, not approximated.

φ̄ per bin Arrival rate from the transient. Negative entries (convolution artefacts) are clamped to zero.
Poisson counts Nb ~ Poisson(φ̄b) — the photon count in the bin, not a yes/no flag.
Dead-time walk Sequential scan over occupied cells tracking t_armed in absolute bins.
Timestamps Int64 (cycle, bin) rows, sorted, not necessarily unique.
Histogram A separate reduction — exactly as real hardware bins a TDC stream after the fact.
Why counts, not Bernoulli. A Bernoulli-per-bin sampler caps detections at one per bin and yields 1 − e−φ instead of φ — a flux-dependent undercount of 4.8% at φ=0.1/bin, 21% at φ=0.5, 37% at φ=1. Drawing the count instead lets the one-detection-per-bin behaviour emerge from the dead time rather than being baked in. Photons within a bin all arrive at the bin centre, so the half-bin offset cancels out of every dead-time comparison and the walk is exact in bin units. The cost: sub-bin dead times are not representable.

Non-paralyzable vs paralyzable the only line that differs

Settings 7 knobs

dead_time_binsint ≥ 0 · default 0
  • 0 — every photon is detected; several photons in one bin each emit a row.
  • > 0 — only the first photon in an occupied bin can fire; the rest sit inside the window it just opened.
  • > n_tbins — supported in free-running mode, because t_armed is tracked in absolute bins rather than modulo the cycle.

Fractional and negative values raise ValueError.

free_runningbool · default True
  • True (asynchronous) — the detector re-arms dead_time_bins after each detection regardless of cycle boundaries. Dead time wraps across cycles. Inherently multi-hit.
  • False (gated / synchronous) — re-armed at every cycle start, so dead time never crosses a boundary. Cycles with no arrivals are skipped entirely.
paralyzablebool · default False
  • False — active quenching: only detections retrigger the dead window.
  • True — passive quenching: every arrival retriggers it, detected or not.
max_detections_per_cycle-1 | None | int ≥ 1 · default -1
  • -1 — per-mode default: 1 when gated, unlimited when free-running.
  • None — unlimited (gated multi-hit).
  • int ≥ 1 — an explicit cap. Free-running rejects any cap.
sparseNone | bool · default None

Arrival-sampling strategy, a pure performance switch. Auto-selects sparse when sum(φ)·n_pulses < 0.25·n_pulses·n_tbins — the normal low-flux regime, where the dense grid would be mostly zeros. The sparse path exploits Poisson superposition (total ~ Poisson(n_pulses·Σφ), each photon then placed uniformly in cycle and categorically in bin), which is exact rather than approximate. Both paths consume the RNG differently, so a fixed seed only reproduces a stream for a fixed choice.

generatortorch.Generator | None

Optional RNG for reproducibility.

n_hist_binstimestamps_to_histogram · default n_tbins

Histogram resolution for the reduction step. A coarser histogram merges adjacent time bins and requires n_tbins to be an exact multiple of n_hist_bins; finer than the TDC is rejected.

TestAnalyticRates 3 functions · 25 cases free-running paralyzable + non-par.

External oracles. The exhaustive test above checks the code against a reference encoding the same semantics, so it cannot catch a physics error common to both. These formulas come independently from renewal theory — the discrete-bin analogues of the textbook counter results λ/(1+λτ) and λe−λτ. Each runs 8 seeds × 60k pulses and applies a z-test at |z| < 4 against the standard error, so the tolerance is derived rather than hand-tuned.

TestcasesLogic
test_non_paralyzable_rate12Renewal argument: each detection is followed by τ dead bins plus a Geometric(p) wait, p = 1−e−λ, giving rate = 1/(τ + (1−p)/p). Swept over λ ∈ {0.01, 0.05, 0.2, 0.5} × τ ∈ {1, 3, 10}. The τ−1 vs τ convention matters here: a detection in bin g blocks g+1 … g+τ−1, leaving g+τ live.
test_paralyzable_rate12A bin detects iff it is occupied and the preceding τ−1 bins are empty, so rate = p·e−λ(τ−1). Same λ × τ sweep.
test_paralyzable_rate_is_non_monotonic_in_flux1The qualitative signature that distinguishes the two devices, and it must emerge from the simulation rather than be asserted anywhere in the code. Across λ up to 1.5 the paralyzable rate must rise then collapse; the non-paralyzable rate must increase monotonically and saturate near 1/τ.
